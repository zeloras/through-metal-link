# 貢献の方法

> [English (primary)](../../CONTRIBUTING.md) · [Русский](../ru/CONTRIBUTING.md) · [Deutsch](../de/CONTRIBUTING.md) · [Português](../pt/CONTRIBUTING.md) · [中文](CONTRIBUTING.md) · 日本語

鋼材の壁を貫くオープン チャネルを進歩させるために貢献したいと思っていただき、ありがとうございます。以下の 3 つのルールは、官僚主義ではありません。プロジェクトの特許の盾 (なぜそうなるのかについては、[LICENSES.md](../../LICENSES.md) を参照してください) です。

## 1. 貢献ライセンス (入力 = 出力)

貢献を提出することで、あなたはそれがそのディレクトリ内の他の資料と同じ方法でライセンスされていることを同意します。

- `software/`、`firmware/` → Apache-2.0;
- `hardware/` → CERN-OHL-W v2;
- `docs/`、`experiments/` → CC-BY-4.0。

**特許免許。** さらに — CC-BY-4.0 は特許をライセンスしていないため — あなたはプロジェクトとその資料のすべての受取人に、貢献を単独でまたはプロジェクトの一部として作成、作成させる、使用、販売のための提供、販売、輸入、およびその他の転送に対する永続的、不可逆的、世界的、ロイヤリティ フリー、非独占的特許免許を付与します。条件は、Apache-2.0 の §3 に従います。貢献が単独で、またはプロジェクトと組み合わせて必然的に侵害されるあなたの特許請求の範囲内で適用されます。如果あなたが (反訴を含む) プロジェクトの資料があなたの特許を侵害しているという申し立てで誰か (プロジェクトやその貢献者を含む) に対して特許訴訟を起こす場合、すべての **特許** 免許がこの条項およびプロジェクトのライセンスの下でプロジェクトおよびその貢献者によってあなたに付与されたものは、訴訟が提出された日の時点で終了します。

## 2. DCO: 起源の署名

各コミットには署名 (`git commit -s`) が付いています。これは、[Developer Certificate of Origin 1.1](https://developercertificate.org/) に同意することを示しています。つまり、あなたはプロジェクトのライセンスの下でこの貢献を提出する権利があることを確認します。

```
Signed-off-by: 氏名 氏名 <email@example.com>
```

署名のない PR はマージされません。チェックは自動化されています。CI ジョブ [.github/workflows/dco.yml](../../.github/workflows/dco.yml) は、署名のないコミットが 1 つでもある場合、PR に失敗します。ドキュメント レイヤーの特許保護は、正確にこのチェーンに依存しています — 例外はありません。

**レイヤー間の資料の移動。** 資料は、着陸したレイヤー (およびそのレイヤーのライセンスの下) に存在します。ライセンスの異なるレイヤー間でテキスト/コードを移動することは、自分の資料である場合、または元のライセンスの明示的な注釈がある場合のみ許可されます。

## 3. 特許衛生と実験プロトコル

- すべての技術的決定は、無料の情報源 (期限切れの特許または [docs/01-prior-art.md](../../docs/01-prior-art.md) の論文) に遡る必要があります。有効な特許請求の実装は、請求が期限切れになるまで受け入れられません。
- 実験結果 — [experiments/TEMPLATE.md](../../experiments/TEMPLATE.md) テンプレートを介してのみ: 日付の付いた再現可能なプロトコルは、正確に私たちの先行技術を構成します。
- アーキテクチャの決定は、[docs/decisions/](../../docs/decisions) の ADR を介して行われます。
- コードのコメント、ドキュメンテーション文字列、識別子、およびコミット メッセージは英語のみです。ドキュメントは多言語 (以下参照) です。ユーザーが見える図のラベルは `labels.json` に格納されます。

## 4. 多言語ドキュメント: 一つの言語を編集し、CI が残りを同期する

英語はプライマリ言語であり、標準的なパスを所有しています。他の言語はすべて、同じファイル名を持つ [translations/](..) の下にあるミラーツリーです。マークダウン、BOM CSV、および生成された図を含みます。図のテキストは `labels.json` によって駆動されます。あなたは手動でミラーを維持する必要は **ありません**:

- あなたに都合の良い言語を編集します。プッシュ時に、[Translation sync](../../.github/workflows/translate.yml) ワークフローは GitHub モデル (`meta/llama-3.3-70b-instruct`、API キーは不要) を使用して、対となる言語を翻訳し、`labels.json` の更新によって図を再生成し、結果を `[translate-sync]` マーカーでコミットします。
- 未完了の作業は `translations/.sync-state.json` に追跡されます。このファイルには、各翻訳が作成されたプライマリ コンテンツが記録されます。クォータまたはタイムアウトによって中断された実行では、作業は失われません。未完了のペアは、次のプッシュまたは夜間実行によって再開されます。このファイルを手動で編集しないでください。
- あなたが **複数** の言語のドキュメントを自分で編集した場合、あなたが編集したバージョンはすべて保持されます。ボットはあなたが編集しなかった言語のみを埋めます。
- 機械翻訳はコミットされます。ボットのコミットをスキマして、トーンを逃さないように単語を調整してください。あなたの修正は上書きされません (ボットはあなたのバージョンを現在のものとして記録します)。
- トランケートされた返信や、`labels.json` プレースホルダが混在した返信は、コミットされず、ペアは再試行されます。ミラーに奇妙なギャップがある場合は、古いペアです。決定ではありません。
- **外部 PR:** ボットは `master` で実行されるため、PR は 1 つの言語のみを変更する可能性があります。ミラー (英語を含む) はマージ後に自動的に追いつきます。あなたはドキュメントに貢献するために英語を知る必要はありません。
- **言語の追加:** 言語コードと名前を [i18n.json](../../i18n.json) (例: `"fr": "Français"`) に追加し、プッシュしてください。パイプラインは、完全な `translations/fr/` ミラーを構築します。すべてのドキュメント、各 `labels.json` に `fr` セクション、図のセット、およびすべての言語スイッチャーが含まれます。
- **非ラテン文字 (CJK など):** 図のレンダリングでは、現在ラテン文字 + キリル文字のフォントのみが付属しています。たとえば、日本語を i18n.json に追加する前に、CJK フォントをレンダリング スクリプトに接続する必要があります。まず、問題を提起してください。

## 5. プッシュ前に実行できるチェック

```bash
python tools/check_repo.py
```

翻訳ボットが破壊できるものと、他のものが捕捉できないものを確認します。すべての相対リンクは解決され、すべての `labels.json` セクションは `i18n.json` と一致し、同じキーと同じ `str.format` プレースホルダを持ち、すべての標準ドキュメントにはすべての言語のミラーがあり、すべてのマークダウン ファイルには言語バーがあります。CI は両方のワークフローで実行され、依存関係は必要ありません。

CI の残り ([ci.yml](../../.github/workflows/ci.yml)) はスクリプトをコンパイルし、図のパイプラインを実行します。コミットされた図を含め、正確に再現するには、固定ツールチェーンをインストールしてください。ローズツールチェーンではありません。

python -m pip install -r tools/requirements-ci.txt
