# コントリビューションの方法

> [English (primary)](../../CONTRIBUTING.md) · [Русский](../ru/CONTRIBUTING.md) · [Deutsch](../de/CONTRIBUTING.md) · [Português](../pt/CONTRIBUTING.md) · [Español](../es/CONTRIBUTING.md) · [Français](../fr/CONTRIBUTING.md) · [Italiano](../it/CONTRIBUTING.md) · [Polski](../pl/CONTRIBUTING.md) · [Türkçe](../tr/CONTRIBUTING.md) · [Українська](../uk/CONTRIBUTING.md) · [Tiếng Việt](../vi/CONTRIBUTING.md) · [中文](../zh/CONTRIBUTING.md) · 日本語 · [한국어](../ko/CONTRIBUTING.md) · [हिन्दी](../hi/CONTRIBUTING.md)

鋼壁貫通チャネルのオープン化を推進しようとしていただき、ありがとうございます。以下の3つのルールは単なる事務手続きではなく、プロジェクトの特許防衛策です（理由は [LICENSES.md](LICENSES.md) を参照してください）。

## 1. コントリビューションのライセンス（インバウンド＝アウトバウンド）

コントリビューションを投稿することにより、そのコントリビューションが配置されるディレクトリの残りの資料と同じライセンスで提供されることに同意したものとみなされます。

- `software/`, `firmware/` → Apache-2.0;
- `hardware/` → CERN-OHL-W v2;
- `docs/`, `experiments/` → CC-BY-4.0.

**特許許諾。** さらに — CC-BY-4.0 は特許を許諾しないため — あなたはプロジェクトおよびその資料のすべての受領者に対し、あなたのコントリビューションを単独で、またはプロジェクトの一部として、製造、委託製造、使用、販売の申出、販売、輸入、その他の移転を行うための、永続的、取消不能、世界的、無償、非独占的な特許ライセンスを付与します — ただし、コントリビューション単独で、または投稿先のプロジェクトとの組み合わせによって必然的に侵害されるあなたの特許請求項の範囲に限られます。条項は Apache-2.0 の §3 に準拠し、コントリビューションがどのディレクトリに配置されたかに関わりません。プロジェクトの資料があなたの特許を侵害していると主張して、あなたが誰かに対して特許訴訟（反訴を含む）を提起した場合、この条項およびプロジェクトのライセンスに基づいてプロジェクトおよびそのコントリビューターからあなたに付与されたすべての**特許**ライセンスは、その訴訟が提起された日付をもって終了します。

## 2. DCO：由来に関する署名

すべてのコミットには署名（`git commit -s`）が付与され、[Developer Certificate of Origin 1.1](https://developercertificate.org/) への同意を示します。あなたは、プロジェクトのライセンスの下でこのコントリビューションを投稿する権利を有することを確認します。

```
Signed-off-by: Firstname Lastname <email@example.com>
```

署名のない PR はマージされません。チェックは自動化されており、CI ジョブ [.github/workflows/dco.yml](../../.github/workflows/dco.yml) は、1件でも署名のないコミットがあれば PR を失敗させます。docs 層の特許保護はまさにこの連鎖に依存しています — 例外はありません。

**レイヤー間の資料移動。** 資料は配置されたレイヤー（およびそのレイヤーのライセンス）に属します。異なるライセンスを持つレイヤー間でテキストやコードを移動する場合、自分自身の資料であるか、断片の元のライセンスを明記した注記がある場合にのみ許可されます。

## 3. 特許衛生管理と実験プロトコル

- すべての技術的決定はフリーな情報源 — 有効期限切れの特許または [docs/01-prior-art.md](docs/01-prior-art.md) の論文 — に遡れなければなりません。存続中の請求項（そこにもリストされています）の実装は、その請求項が期限切れになるまで受け付けられません。
- 実験結果は [experiments/TEMPLATE.md](experiments/TEMPLATE.md) テンプレート経由のみ — 日付付きの再現可能なプロトコルこそが、私たちの先行技術を構成するものです。
- アーキテクチャの決定は [docs/decisions/](docs/decisions/) の ADR を経て行われます。
- コードコメント、ドックストリング、識別子、コミットメッセージは英語のみです。ドキュメントは多言語対応（後述）。ユーザーに表示される図のラベルは `labels.json` に格納されます。

## 4. 多言語ドキュメント：1つの言語を編集すれば、CI が残りを同期

英語が一次言語であり、正規のパスを所有します。その他のすべての言語は [translations/](..) 配下のミラーツリーで、ファイル名は同一 — markdown、BOM CSV、生成された図も含みます。図のテキストは `labels.json` で駆動します。ミラーを手動で保守する必要は**ありません**。

- 使いやすい言語をどれでも編集してください。プッシュ時に、[Translation sync](../../.github/workflows/translate.yml) ワークフローがオープンウェイトの LLM（Ollama Cloud 上の `glm-5.2`）で対応する翻訳を生成し、同期が `labels.json` を更新したときに図を再生成し、`[translate-sync]` マーカー付きで結果をコミットし直します。OpenAI 互換のエンドポイントなら何でも動作します — `OPENAI_BASE_URL` と `TRANSLATE_MODEL` を設定してください。
- まだ作業が必要なものは `translations/.sync-state.json` で追跡されます。このファイルは各翻訳が元にした一次コンテンツを記録しています。そのため、クォータやタイムアウトで中断された実行でも何も失われません — 未完了のペアは古い状態のままマークされ、次のプッシュまたは夜間実行で再処理されます。このファイルを手動で編集しないでください。
- 自分でドキュメントの**複数の**言語を編集した場合、あなたが編集したすべてのバージョンはそのまま保持されます。ボットはあなたが編集していない言語のみを補完します。
- **`labels.json` は「どの言語でも編集可」の例外です。** 図のラベルは一次 → ミラーへの一方向のみに流れます。翻訳されたラベルを編集するとその言語が修正され、そこで止まります — 英語には逆流しません。ラベルの*内容*を変更するには、一次セクションを編集してください。理由は非対称性です — ラベルの編集はほぼ常に機械翻訳の表現を人が修正するものであり、それに一次を書き換えさせると、14のミラーすべての生成元が再定義されてしまいます。ボットが一度も生成したことのないキーは逆伝播するため、手書きのラベルが1つの言語に留まることはありません。
- 機械翻訳はコミットされます — ボットのコミットをざっと確認し、トーンが合わなければ表現を調整してください。あなたの修正は上書きされません（ボットはあなたのバージョンを現行として記録します）。
- 切り詰められたり `labels.json` のプレースホルダが壊れたりした応答はコミットされずに破棄され、そのペアは再試行されます — したがって、ミラーに奇妙な欠落があっても、それは何らかの決定ではなく、古いペアです。
- **外部 PR：** ボットは `master` で実行されるため、PR は1つの言語のみを変更できます — マージ直後にミラー（英語を含む）が自動的に追いつきます。ドキュメントにコントリビュートするために英語を知る必要はありません。
- **言語の追加：** [i18n.json](../../i18n.json) にその言語コードと名前を追加し（例：`"fr": "Français"`）、プッシュするだけです — パイプラインが `translations/fr/` ミラーツリー全体を構築します — すべてのドキュメント、各 `labels.json` の `fr` セクション、図セット、そしてすべての場所の言語切り替えリンクです。
- **非ラテン文字スクリプト：** CI は Noto フォントファミリー（`fonts-noto-core`, `fonts-noto-cjk`）をインストールし、レンダラーは `i18n.json` → `render.fonts` のフォントスタックを走査するため、キリル文字、漢字、仮名、ハングルが正しく出力されます。レンダラーは描画前にグリフカバレッジをチェックし、**`.notdef` ボックスを描画する代わりに失敗します** — このチェックが存在するのは、中国語の図が豆腐のグリッドとして出荷され、CI のどこもピクセルを見ていないからです。これが発火したら、そのスクリプト用の Noto フェイスをスタックに追加してください。
- **文脈依存のシェイピングが必要なスクリプト** — アラビア語とペルシャ語（RTL、結合形）、デーヴァナーガリーとベンガル語（結合子） — は、シェイピングエンジンを持たない matplotlib では正しく描画できません。正しいフォントがあってもグリフは結合されず、順序も乱れます。それらの言語は `i18n.json` → `render.skip_figures` にリストしてください。それらの本文は影響を受けません。ドキュメントは単に一次図へのリンクを使用し、[tools/translate_sync.py](../../tools/translate_sync.py) のリンク修復が自動的にリンク先を修正します。`hi` はこのように設定されています。
- **スクリプトガード：** [tools/i18n_render.py](../../tools/i18n_render.py) の `SCRIPTS` は、各言語のラベルにどのスクリプトが含まれていなければならないかを記録しています。そのスクリプトが1つも含まれない応答 — かつて `ja` セクションがロシア語で埋められて出荷されたことがあります — は拒否され、コミットされる代わりに再試行されます。そのテーブルに存在しない言語は単にガードを受けないため、`i18n.json` に追加しても壊れることはありません。チェックを有効にするにはエントリを追加してください。

## 5. プッシュ前に実行できるチェック

```bash
python tools/check_repo.py
```

翻訳ボットが壊す可能性があり、他では検出できないものを検証します — すべての相対リンクが解決されること、すべての `labels.json` セクションが `i18n.json` に一致し、一次セクションと同じキーと同じ `str.format` プレースホルダを持つこと、すべての正規ドキュメントがすべての言語にミラーを持つこと、すべての markdown ファイルに言語バーがあることです。CI は両方のワークフローでこれを実行します。依存関係は不要です。

CI の残り（[ci.yml](../../.github/workflows/ci.yml)）はスクリプトをコンパイルし、図パイプライン全体を実行します。コミットされた図を含めて正確に再現するには — 緩いツールチェーンではなく、ピン留めされたツールチェーンをインストールしてください。

```bash
python -m pip install -r tools/requirements-ci.txt
```
