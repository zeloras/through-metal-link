鋼壁貫通チャネルのオープン化を推進しようとしてくださり、ありがとうございます。以下の3つのルールは単なる事務手続きではありません — これらは本プロジェクトの特許防護です（理由については [LICENSES.md](LICENSES.md) を参照してください）。

## 1. 貢献ライセンス (インバウンド = アウトバウンド)

コントリビューションを提出することにより、それはそのディレクトリ内の他の資料と同じ方法でライセンスされることに同意したものとみなされます:

- `software/`, `firmware/` → Apache-2.0;
- `hardware/` → CERN-OHL-W v2;
- `docs/`, `experiments/` → CC-BY-4.0.

**特許の許諾。** 加えて — CC-BY-4.0 は特許をライセンスしないため — あなたは、プロジェクトおよびその資料のすべての受領者に対し、あなたのコントリビューションを単独で、またはプロジェクトの一部として、製造、製造委託、使用、販売の申出、販売、輸入、その他の方法で移転するための、永続的、取消不能、世界的、ロイヤリティフリー、非独占的な特許ライセンスを許諾します — ただし、コントリビューション単独で、またはそれが提出されたプロジェクトとの組み合わせによって必然的に侵害されるあなたの特許請求の範囲に限られます。コントリビューションがどのディレクトリに配置されたかに関わらず、条項は Apache-2.0 の §3 に従います。あなたが、プロジェクトの資料があなたの特許を侵害しているとして、いかなる者に対しても特許訴訟（反訴を含む）を提起した場合、プロジェクトの資料に対するあなたのすべての**特許**ライセンス — 本条項およびプロジェクトのライセンスの下でプロジェクトおよびそのコントリビューターからあなたに許諾されたもの — は、当該訴訟が提起された日付をもって終了します。

## 2. DCO: 由来に対する署名

Signed-off-by: Firstname Lastname <email@example.com>
```

サインオフのないPRはマージされません。チェックは自動化されています — 1つのコミットでもサインオフが欠落していると、CIジョブ [.github/workflows/dco.yml](../../.github/workflows/dco.yml) がPRを失敗させます。ドキュメント層の特許保護はまさにこの連鎖に依存しています — 例外はありません。

**レイヤー間での素材の移動。** 素材はそれが配置されたレイヤー（およびそのレイヤーのライセンスの下）に存在します。異なるライセンスを持つレイヤー間でテキストやコードを移動することは、それが自身の素材である場合、またはフラグメントの元のライセンスに関する明示的な注記がある場合にのみ許可されます。

## 3. 特許衛生と実験プロトコル

- すべての技術的決定はフリーな情報源に遡る必要があります — 期限切れの特許や [docs/01-prior-art.md](docs/01-prior-art.md) の論文など。存続中のクレーム（そこにもリストされています）の実装は、そのクレームが期限切れになるまで受け付けられません。
- 実験結果 — [experiments/TEMPLATE.md](experiments/TEMPLATE.md) テンプレート経由のみ：日付付きの再現可能なプロトコルこそが、私たちの先行技術を構成するものです。
- アーキテクチャの決定は [docs/decisions/](docs/decisions/) の ADR を経由します。
- コードコメント、ドックストリング、識別子、コミットメッセージは英語のみです。ドキュメントは多言語対応です（後述）。ユーザーに表示される図のラベルは `labels.json` に配置します。

## 4. 多言語ドキュメント: 一言語を編集、CIが残りを同期

英語が主言語であり、正規のパスを所有しています。他のすべての言語は [translations/](..) の下にあるミラーツリーであり、ファイル名は同一です — マークダウン、BOM CSV、生成された図も含まれます。図のテキストは `labels.json` によって駆動されます。ミラーを手動で維持する必要は**ありません**。

- 扱いやすい言語を編集してください。プッシュすると、[Translation sync](../../.github/workflows/translate.yml) ワークフローがオープンウェイトのLLM（Ollama Cloud上の `glm-5.2`）で対応する翻訳を行い、同期が `labels.json` を更新したときに図を再生成し、結果を `[translate-sync]` マーカーと共にコミットします。OpenAI互換のエンドポイントなら何でも機能します — `OPENAI_BASE_URL` と `TRANSLATE_MODEL` を設定してください。
- まだ作業が必要なものは `translations/.sync-state.json` で追跡され、そこには各翻訳がどの主言語のコンテンツから作成されたかが記録されます。そのため、クォータやタイムアウトで中断された実行でも何も失われません：未完了のペアは古い状態のままマークされ、次のプッシュまたは夜間の実行で拾われます。このファイルを手動で編集しないでください。
- あなた自身がドキュメントの**複数の**言語を編集した場合、あなたが触れたすべてのバージョンはあなたが書いた通りに保持されます。ボットはあなたが触れていない言語のみを埋めます。
- **`labels.json` は「任意の言語を編集」の例外です。** 図のラベルは主言語 → ミラーのみに流れます。翻訳されたラベルを編集するとその言語が修正され、そこで止まります。英語には戻りません。ラベルが*言うこと*を変更するには、主言語のセクションを編集してください。理由は非対称性です。ラベルの編集はほぼ常に誰かが機械の言葉を修正することであり、それに主言語を書き換えさせると、14のミラーすべてが生成されるソースが再定義されてしまいます。ボットが生成したことのないキーは伝播して戻るため、手作成のラベルが一つの言語に留まることはありません。
- 機械翻訳はコミットされます — ボットのコミットをざっと確認し、トーンが合わない場合は言葉を調整してください。あなたの修正は上書きされません（ボットはあなたのバージョンを現在のものとして記録します）。
- 切り詰められたり、`labels.json` のプレースホルダーが破損して返された応答はコミットされずに破棄され、ペアは再試行されます — したがって、ミラーの奇妙な隙間は古いペアであり、決定ではありません。
- **外部PR：** ボットは `master` で実行されるため、PRは1つの言語のみを変更する可能性があります — ミラー（英語を含む）はマージ直後に自動的に追いつきます。ドキュメントに貢献するために英語を知る必要はありません。
- **言語の追加：** [i18n.json](../../i18n.json) にコードと名前を追加し（例：`"fr": "Français"`）、プッシュします — パイプラインが `translations/fr/` ミラー全体を構築します：すべてのドキュメント、各 `labels.json` の `fr` セクション、図のセット、そしてあらゆる場所の言語切り替え機能です。
- **非ラテン文字スクリプト：** CIはNotoファミリー（`fonts-noto-core`、`fonts-noto-cjk`）をインストールし、レンダラーは `i18n.json` → `render.fonts` のフォントスタックを走査するため、キリル文字、漢字、かな、ハングルが正しく表示されます。レンダラーは描画前にグリフカバレッジをチェックし、`.notdef` ボックスを描画する**代わりに失敗します** — このチェックが存在するのは、中国語の図が豆腐のグリッドとして出荷され、CI内でピクセルを見るものが何もないからです。これが発動した場合は、そのスクリプトのNotoフォントをスタックに追加してください。
- **文脈によるシェイピングが必要なスクリプト** — アラビア語とペルシャ語（RTL、結合形）、デーヴァナーガリーとベンガル語（結合子） — は、シェイピングエンジンを持たないmatplotlibでは正しく描画できません：適切なフォントがあってもグリフは結合されず、順序も狂ってしまいます。これらの言語を `i18n.json` → `render.skip_figures` にリストしてください。それらの散文は影響を受けません。それらのドキュメントは単に主言語の図にリンクされ、[tools/translate_sync.py](../../tools/translate_sync.py) のリンク修復が自動的にそれを指すようにします。`hi` はこのように設定されています。
- **スクリプトガード：** [tools/i18n_render.py](../../tools/i18n_render.py) の `SCRIPTS` は、各言語のラベルにどのスクリプトが含まれていなければならないかを記録します。それが一つもない応答 — `ja` セクションがかつてロシア語でいっぱいになって出荷されたように — は拒否されてコミットされる代わりに再試行されます。そのテーブルにない言語は単にガードを持たないため、`i18n.json` に追加しても壊れることはありません。チェックを得るにはエントリを追加してください。

## 5. プッシュ前に実行できるチェック

python tools/check_repo.py
```

翻訳ボットが壊しうるもので他には何も検出できないものを検証します: すべての相対リンクが解決されること、すべての `labels.json` セクションが `i18n.json` と一致し、プライマリと同じキーと同じ `str.format` プレースホルダーを持つこと、すべての正規ドキュメントが各言語にミラーを持つこと、そしてすべてのMarkdownファイルに言語バーがあること。CIは両方のワークフローでこれを実行します。依存関係は不要です。

CIの残りの部分（[ci.yml](../../.github/workflows/ci.yml)）はスクリプトをコンパイルし、図のパイプライン全体を実行します。コミット済みの図を含めて正確に再現するには、緩いツールチェーンではなく、ピン留めされたツールチェーンをインストールしてください:

```bash
python -m pip install -r tools/requirements-ci.txt
