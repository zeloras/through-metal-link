このスキームの目的: プロジェクトは完全にオープンであり、誰でもフォークしてビルドできる (商用を含む)。同時に、特許訴訟のリスクを、法的および手続き上の手段によって到達可能な最小限にまで抑える。

## スキーム (3 つのレイヤー; 全文は [LICENSES/](../../LICENSES) に)

| エリア | ライセンス | テキスト | 特許条項 |
|---|---|---|---|
| `software/`、`firmware/` | Apache-2.0 | [LICENSES/Apache-2.0.txt](../../LICENSES/Apache-2.0.txt) | §3: すべてのコントリビューターはそのコントリビューションに対して自動的に特許ライセンスを付与する; 特許訴訟を起こすと**特許**ライセンスを失う (報復; §2 の著作権ライセンスは不可逆であり、訴訟後も存続する) |
| `hardware/` | CERN-OHL-W v2 | [LICENSES/CERN-OHL-W-2.0.txt](../../LICENSES/CERN-OHL-W-2.0.txt) | §7.1: すべてのライセンサーから特許ライセンス (製造 / 製造させる / 使用 / 販売 / 輸入…) — ただし、特定のカバードソースによって必然的に侵害される請求項にのみ; §7.2: 特許訴訟 (他者の特許を無効化する試みを含む) は、ライセンス下の**すべて**の権利を終了する |
| `docs/`、`experiments/` | CC-BY-4.0 | [LICENSES/CC-BY-4.0.txt](../../LICENSES/CC-BY-4.0.txt) | **特許権を付与しない** (§2(b)(2)) — このギャップは [CONTRIBUTING.md](CONTRIBUTING.md) における明示的な特許付与によって埋められる |
| それ以外のすべて (ルート `README.md`、`QUICKSTART.md`、このファイル、`data/` など) | CC-BY-4.0 | — | フォールバック: リポジトリ内のファイルはいずれも「すべての権利予約」にならない |

コードファイルには SPDX ヘッダー (Apache-2.0) が付与される; マシンリーダブルなカバレッジマップは [REUSE.toml](../../REUSE.toml) である。著作権行は [NOTICE](../../NOTICE) にある; ルート [LICENSE](../../LICENSE) はこのスキームへのポインタである。

**CERN-OHL-W を使用する理由 (S や P ではなく)。** W は中間的な立場である: 設計とその修正はどの配布でもオープンに保たれなければならないが、設計が組み込まれる製品は商用かつプロプライエタリであり得る — これにより docs/05 (研究所、醸造所、バッテリーパック) からのニッチが開かれる。S (強いコピーレフト) は組み込みの扉を閉ざす; P (許容的) はクローズドフォークを許す。S への引き締めはライセンス自体に組み込まれている: §8.3 は、誰もが W ライセンス素材を S ライセンスとして扱える (利用可能コンポーネント条件が満たされている場合) — 許可は不要。一方、緩和 (P や他のライセンスへ) は、すべての素材が単一の著者に属する間のみ可能である; 最初の外部コントリビューション後は — すべてのコントリビューターの同意が必要である。

**プロジェクト名。** "through-metal-link" は登録商標ではない; ライセンス自体は名前に対する権利を付与しない (Apache §6、CC-BY §2(b)(2)、CERN-OHL-W §8.2)。プロジェクトへの事実に基づく言及 ("through-metal-link に基づく") は誰でも自由である; 互換性のない変更を加えたフォークには、独自の名前で出荷することが求められる。

## これが保護するもの — そして保護しないもの (正直に)

**保護するもの:**
1. **コントリビューターからの訴訟。** コントリビュートした者は誰も、そのコントリビューションに対する特許権を自動的にライセンスしている (Apache §3、CERN-OHL §7.1、および docs 用の CONTRIBUTING)。訴訟は原告に高くつく: Apache-2.0 の下ではコードに対する特許ライセンスを失う; CERN-OHL-W の下ではハードウェアレイヤーに対する**すべて**の権利を即座に失う (§7.2 — 他者の特許に異議を唱える試みによってさえトリガーされる)。
2. **ハードウェアフォークの民営化。** CERN-OHL-W は、配布 (製品またはソースの伝達) する者に設計修正の公開を義務付ける — 改善はオープンレイヤーに還流し、それ自体が先行技術になる。(第三者に伝達されない引き出しの中のフォークには公開義務がない — いかなるコピーレフトと同様。)
3. **他人の *将来* の特許。** 日付付きで公開されたすべては、後の出願に対する新規性を破壊する: その出願日より前にここで記述された解決策に対して、有効な特許はもはや付与されない。我々の公開 *より前に* 出願された出願に対してはこれは機能しない — それらに対して唯一の盾は、期限切れ特許レイヤーである (以下参照)。

**保護しないもの:**
- **すでに存在する第三者の特許。** どのライセンスもそれに対処できない。対処できるのは docs/01-prior-art.md の技術規律である: 期限切れレイヤー (パブリックドメイン) からのみ構築し、そこに記載された有効な請求項 (RPI、Drexel、および 2026-08 に追加された Navy/ABB/Ultrapower ファミリー — これらはすべて米国のみではなく、すべてが 2032 年頃に期限切れになるわけでもないことに注意) を実装せず、すべての設計決定を自由なソースに遡る。保証ではないが、訴訟を無意味にするのはまさにこの実践である。
- 商用生産に向けたフォークは、自身の管轄区域と設計について独自の FTO (freedom to operate) 分析を行う — リポジトリは特許表明を行わない (3 つのライセンスすべてに免責条項がある)。

## 防御公開プロトコル (マイルストーン公開のたびに実行を続ける)

公開されたすべての結果は、同一の解決策に対する後続の第三者出願をブロックする、日付付きの先行技術である:

1. 完全な公開 git 履歴を維持する (コミット = タイムスタンプ)。
2. **Zenodo** にスナップショット → DOI: 法的に意味のある日付を持つ独立したアーカイブ、論文で引用可能。
3. **Software Heritage** (archive.softwareheritage.org — 永続的なミラー) にピン留めする。
4. 完了したすべての実験 `experiments/NNN` — 日付、数値、プロット付き: これは特定の技術的解決策の公開である。
5. 主要なマイルストーン (最初のワット、最初のノード) — 広く世に出す書き込み (Hackaday.io / arXiv / ブログ): 広く広がるほど、先行技術の地位は強くなる。

## コントリビューター向け

ルールは [CONTRIBUTING.md](CONTRIBUTING.md) にある: DCO サインオフ、インバウンド = アウトバウンド、ディレクトリに関係なくすべてのコントリビューションに対する明示的な特許付与、設計決定の自由な先行技術への追跡可能性。

リポジトリはすでに公開されている。各マイルストーンで上記のプロトコルを継続する (Zenodo スナップショット、Software Heritage ピン留め、実験書き込み) — これにより、結果が出るたびに日付付き先行技術が強力なまま保たれる。
