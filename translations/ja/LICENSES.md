# ライセンスと特許保護

> [English (primary)](../../LICENSES.md) · [Русский](../ru/LICENSES.md) · [Deutsch](../de/LICENSES.md) · [Português](../pt/LICENSES.md) · [中文](../zh/LICENSES.md) · 日本語

このスキームの目的: プロジェクトは完全にオープンであり、誰でもフォークしてビルドできます (商用を含む)。同時に、法的および手続き上の手段によって、特許訴訟のリスクを最小限に抑える。

## スキーム (3 つのレイヤー; 全文は [LICENSES/](../../LICENSES) に)

| エリア | ライセンス | テキスト | 特許条項 |
|---|---|---|---|
| `software/`、`firmware/` | Apache-2.0 | [LICENSES/Apache-2.0.txt](../../LICENSES/Apache-2.0.txt) | §3: すべてのコントリビューターは自動的に特許ライセンスを付与する; 特許訴訟を起こすと、**特許** ライセンスを失う (報復; 著作権ライセンスは §2 において不可逆的に残存する) |
| `hardware/` | CERN-OHL-W v2 | [LICENSES/CERN-OHL-W-2.0.txt](../../LICENSES/CERN-OHL-W-2.0.txt) | §7.1: すべてのライセンサーから特許ライセンス (製造 / 製造されたもの / 使用 / 販売 / 輸入…) ; §7.2: 特許訴訟 (他者の特許の無効化を試みることを含む) は、**すべて** のライセンス下の権利を終了する |
| `docs/`、`experiments/` | CC-BY-4.0 | [LICENSES/CC-BY-4.0.txt](../../LICENSES/CC-BY-4.0.txt) | **特許権を付与しない** (§2(b)(2)) — このギャップは、[CONTRIBUTING.md](../../CONTRIBUTING.md) における明示的な特許付与によって埋められる |
| それ以外のすべて (ルート `README.md`、`QUICKSTART.md`、このファイル、`data/` など) | CC-BY-4.0 | — | フォールバック: リポジトリ内のファイルはすべて "すべての権利予約" にならない |

コードファイルにはSPDXヘッダー (Apache-2.0) が付与される; マシンリーダブルなカバレッジマップは [REUSE.toml](../../REUSE.toml) である。著作権行は [NOTICE](../../NOTICE) にある; ルート [LICENSE](../../LICENSE) はこのスキームへのポインタである。

**CERN-OHL-W を使用する理由 (S や P ではなく)**。W は中間の地平線である: 設計とその修正はどの配布でもオープンである必要があるが、設計が構築される製品は商用および独自のものになる可能性がある — これにより、ドキュメント/05 (研究所、醸造所、バッテリーパック) からのニッチが開かれる。S (厳格なコピーレフト) は埋め込みのドアを閉じる; P (許容的なライセンス) はクローズドフォークを許可する。S に向けた引き締めは、ライセンス自体に組み込まれている: §8.3 は、誰でも W ライセンスされた素材を S ライセンスされたものとして扱うことを許可する (利用可能なコンポーネント条件が満たされている場合); 許可は必要ない。逆に、緩和 (P または別のライセンスに近づく) は、すべての素材が単一の著者に属する間のみ可能である; 最初の外部コントリビューション後に — すべてのコントリビューターの同意が必要である。

**プロジェクト名**。"through-metal-link" は登録商標ではない; ライセンス自体は名前に対する権利を付与しない (Apache §6、CC-BY §2(b)(2)、CERN-OHL-W §8.2)。事実に基づいてプロジェクトに言及する ("through-metal-link に基づく") は、誰でも自由である; 不相容な変更を持つフォークは、独自の名前で出荷するように求められる。

## これが保護するもの — と保護しないもの (誠実に)

**これが保護するもの:**
1. **コントリビューターからの訴訟**。誰でもコントリビュートした人は自動的にそのコントリビューションに対する特許権をライセンスする (Apache §3、CERN-OHL §7.1、およびドキュメント用の [CONTRIBUTING](../../CONTRIBUTING.md))。訴訟を起こすと、被告は高くつく: Apache-2.0 の下では **特許** ライセンスを失う; CERN-OHL-W の下ではハードウェアレイヤーに対する **すべて** の権利を失う (§7.2 — 他者の特許に異議を唱えることを含むすべての訴訟によってトリガーされる)。
2. **ハードウェアフォークの民営化**。CERN-OHL-W は、誰でも配布 (製品またはソースの伝達) する場合に、設計の修正を公開することを義務付ける — 改善はオープンレイヤーに戻り、自分で先行技術になる。 (第三者に伝達されていないドロワー フォークには公開義務がない — すべてのコピーレフトと同様に。)
3. **他人の *将来* の特許**。ここで公開されたすべては、後から出願された特許に対する新規性を破壊する: ここで前に記述された解決策に対して、有効な特許はもう与えられない。ここで公開される *以前に* 出願された特許に対しては、これは機能しない — その場合、唯一の盾は期限切れの特許レイヤー (以下参照) である。

**これが保護しないもの:**
- **すでに存在する第三者の特許**。どのライセンスもそれに対処できない。対処できるのは、docs/01-prior-art.md の技術規律: 公共ドメイン (期限切れ) からのみ構築し、有効な請求 (RPI OFDM/フルデュプレックス、Drexel — ~2032 年まで、米国のみ) を実装しない; すべての設計決定を自由なソースに遡る。保証ではないが、訴訟を無意味にするのは、正確にこの実践である。
- 商用生産に向けたフォークは、独自の管轄区域と設計に対する独自の FTO (運用の自由) 分析を行う — リポジトリは特許表明を行わない (すべてのライセンスに免責がある)。

## 防御公開プロトコル (リポジトリが公開されたときに実行)

公開されたすべての結果は、後から出願されたすべての第三者の出願に対して同一の解決策をブロックする、日付付きの先行技術である:

1. リポジトリを完全な Git履歴 (コミット = タイムスタンプ) で開く。
2. **Zenodo** へのスナップショット → DOI: 法的に意味のある日付を持つ独立したアーカイブ、論文で引用可能。
3. **Software Heritage** (archive.softwareheritage.org — 永続的なミラー) にピン留めする。
4. すべての完了した実験 `experiments/NNN` — 日付、数字、プロット付き: これは、特定の技術的解決策の公開である。
5. 主要なマイルストーン (最初のワット、最初のノード) — 世界中で書き出し (Hackaday.io / arXiv / ブログ): 広く広がるほど、先行技術の地位は強くなる。

## コントリビューター向け

ルールは [CONTRIBUTING.md](../../CONTRIBUTING.md) にある: DCO サインオフ、インバウンド = アウトバウンド、すべてのコントリビューションに対する明示的な特許付与 (ディレクトリに関係なく)、先行技術への設計決定の追跡可能性。

再現可能な結果が最初に得られるまで、リポジトリは非公開のままにする — 最初の結果が出る前に公開すると、科学的および特許の立場が弱まる。
