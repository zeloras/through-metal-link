> [English (primary)](../../CONTRIBUTING.md) · [Русский](../ru/CONTRIBUTING.md) · [Deutsch](../de/CONTRIBUTING.md) · [Português](../pt/CONTRIBUTING.md) · [Español](../es/CONTRIBUTING.md) · [Français](../fr/CONTRIBUTING.md) · [Italiano](../it/CONTRIBUTING.md) · [Polski](../pl/CONTRIBUTING.md) · [Türkçe](../tr/CONTRIBUTING.md) · [Українська](../uk/CONTRIBUTING.md) · [Tiếng Việt](../vi/CONTRIBUTING.md) · [中文](../zh/CONTRIBUTING.md) · [日本語](../ja/CONTRIBUTING.md) · 한국어 · [हिन्दी](../hi/CONTRIBUTING.md)

강철 벽 통과 채널 오픈 프로젝트 발전에 관심 가져주셔서 감사합니다. 아래 세 가지 규칙은 관료주의가 아니라 — 프로젝트의 특허 방어구입니다 (이유는 [LICENSES.md](LICENSES.md)를 참조하세요).

## 1. 기여 라이선스 (인바운드 = 아웃바운드)

기여물을 제출함으로써, 귀하는 해당 기여물이 속한 디렉토리의 나머지 자료와 동일한 방식으로 라이선스가 부여됨에 동의합니다:

- `software/`, `firmware/` → Apache-2.0;
- `hardware/` → CERN-OHL-W v2;
- `docs/`, `experiments/` → CC-BY-4.0.

**특허 허여.** 추가로 — CC-BY-4.0은 특허를 라이선스하지 않으므로 — 귀하는 프로젝트 및 해당 자료의 모든 수령자에게 귀하의 기여물을 단독으로 또는 프로젝트의 일부로서 제조, 제조하게 함, 사용, 판매를 위해 제안, 판매, 수입 및 기타 방식으로 양도할 수 있는 영구적이고 취소 불가능하며 전 세계적이고 로열티가 없는 비독점적 특허 라이선스를 부여합니다. 이는 기여물 자체 또는 기여물이 제출된 프로젝트와의 조합에 의해 필연적으로 침해되는 귀하의 특허 청구항의 범위 내에서 적용됩니다. 이 약관은 기여물이 속한 디렉토리에 관계없이 Apache-2.0의 §3을 따릅니다. 귀하가 프로젝트의 자료가 귀하의 특허를 침해한다고 주장하며 누군가(반소 포함)에 대해 특허 소송을 제기하는 경우, 본 조항 및 프로젝트의 라이선스에 따라 프로젝트 및 그 기여자가 귀하에게 부여한 모든 **특허** 라이선스는 해당 소송이 제기된 날짜부로 종료됩니다.

## 2. DCO: 출처에 대한 서명

Signed-off-by: Firstname Lastname <email@example.com>
```

sign-off가 없는 PR은 병합되지 않습니다. 이 검사는 자동으로 수행됩니다 — 단 하나의 커밋이라도 sign-off가 누락되면 CI 작업 [.github/workflows/dco.yml](../../.github/workflows/dco.yml)이 PR을 실패 처리합니다. 문서 계층의 특허 보호는 정확히 이 연쇄에 기반하며 — 예외는 없습니다.

**계층 간 자료 이동.** 자료는 해당 자료가 속한 계층(및 해당 계층의 라이선스)에 머무릅니다. 서로 다른 라이선스를 가진 계층 간에 텍스트/코드를 이동하는 것은 본인의 자료인 경우에만, 또는 해당 조각의 원래 라이선스를 명시적으로 표기한 경우에만 허용됩니다.

## 3. 특허 위생 및 실험 프로토콜

- 모든 기술적 결정은 무료 소스 — 만료된 특허 또는 [docs/01-prior-art.md](docs/01-prior-art.md)의 논문 — 로 추적 가능해야 합니다. 유효한 청구항(해당 문서에도 나열됨)의 구현은 그 청구항이 만료될 때까지 받아들여지지 않습니다.
- 실험 결과 — [experiments/TEMPLATE.md](experiments/TEMPLATE.md) 템플릿을 통해서만: 날짜가 기재된 재현 가능한 프로토콜이 바로 우리의 선행 기술을 구성합니다.
- 아키텍처 결정은 [docs/decisions/](docs/decisions/)의 ADR을 거쳐 이루어집니다.
- 코드 주석, 독스트링, 식별자 및 커밋 메시지는 영어 전용입니다. 문서는 다국어입니다(아래 참조); 사용자에게 보이는 그림 라벨은 `labels.json`에 있습니다.

## 4. 다국어 문서: 한 언어를 편집하면 CI가 나머지를 동기화합니다

영어가 주 언어이며 정식 경로를 소유합니다. 다른 모든 언어는 [translations/](..) 아래에 동일한 파일 이름을 가진 미러 트리입니다 — 마크다운, BOM CSV 및 생성된 이미지를 포함하며, 이미지 텍스트는 `labels.json`에 의해 구동됩니다. 미러를 수동으로 유지 관리할 **필요는 없습니다**:

- 편안한 언어로 편집하세요. 푸시 시 [Translation sync](../../.github/workflows/translate.yml) 워크플로우가 오픈 웨이트 LLM(Ollama Cloud의 `glm-5.2`)으로 상대편을 번역하고, 동기화가 `labels.json`을 업데이트할 때 이미지를 재생성하며, 결과를 `[translate-sync]` 마커와 함께 다시 커밋합니다. OpenAI 호환 엔드포인트라면 모두 작동합니다 — `OPENAI_BASE_URL`과 `TRANSLATE_MODEL`을 설정하세요.
- 여전히 작업이 필요한 부분은 `translations/.sync-state.json`에서 추적되며, 이 파일은 각 번역이 만들어진 원본 콘텐츠를 기록합니다. 따라서 할당량이나 시간 초과로 인해 중단된 실행은 아무것도 잃지 않습니다: 완료되지 않은 쌍은 오래된 것으로 표시된 채로 남아 다음 푸시나 야간 실행에서 다시 처리됩니다. 이 파일을 수동으로 편집하지 마세요.
- 문서의 **여러** 언어를 직접 편집한 경우, 당신이 수정한 모든 버전은 작성한 대로 유지됩니다. 봇은 당신이 수정하지 않은 언어만 채웁니다.
- **`labels.json`은 "아무 언어로 편집"의 예외입니다.** 이미지 라벨은 원본 → 미러 방향으로만 흐릅니다. 번역된 라벨을 편집하면 해당 언어가 수정되고 거기서 멈춥니다. 영어로 다시 역류하지 않습니다. 라벨이 *말하는 내용*을 변경하려면 원본 섹션을 편집하세요. 그 이유는 비대칭성 때문입니다. 라벨 편집은 거의 항상 기계의 표현을 수정하는 것이며, 이것이 원본을 다시 작성하게 하면 14개의 미러가 생성되는 소스가 재정의됩니다. 봇이 생성한 적이 없는 키는 여전히 역류하여 전파되므로, 직접 작성한 라벨이 한 언어에 갇히지 않습니다.
- 기계 번역은 커밋됩니다 — 봇의 커밋을 훑어보고 어조가 맞지 않으면 표현을 다듬으세요. 수정 사항은 덮어쓰이지 않습니다(봇은 당신의 버전을 현재 버전으로 기록합니다).
- 잘리거나 `labels.json` 플레이스홀더가 손상된 채로 돌아온 응답은 커밋되지 않고 폐기되며, 해당 쌍은 재시도됩니다 — 따라서 미러의 이상하게 보이는 빈 공간은 결정된 것이 아니라 오래된 쌍입니다.
- **외부 PR:** 봇은 `master`에서 실행되므로, PR은 하나의 언어만 변경할 수 있습니다 — 미러(영어 포함)는 병합 직후 자동으로 따라잡습니다. 문서에 기여하기 위해 영어를 알 필요는 없습니다.
- **언어 추가:** [i18n.json](../../i18n.json)에 코드와 이름을 추가하고(예: `"fr": "Français"`) 푸시하세요 — 파이프라인이 전체 `translations/fr/` 미러를 구축합니다: 모든 문서, 각 `labels.json`의 `fr` 섹션, 이미지 세트, 그리고 모든 곳의 언어 전환기.
- **비 라틴 문자:** CI는 Noto 패밀리(`fonts-noto-core`, `fonts-noto-cjk`)를 설치하고 렌더러는 `i18n.json` → `render.fonts`의 폰트 스택을 따르므로 키릴, 한자, 가나, 한글이 올바르게 출력됩니다. 이제 렌더러는 그리기 전에 글리프 커버리지를 확인하고 **`.notdef` 박스를 그리는 대신 실패합니다** — 이 검사가 존재하는 이유는 중국어 이미지가 두부 모양 격자로 출력되었고 CI의 어떤 것도 픽셀을 보지 않았기 때문입니다. 이 검사가 발동하면 해당 문자의 Noto 폰트를 스택에 추가하세요.
- **문맥 형태 변화가 필요한 문자** — 아랍어와 페르시아어(RTL, 연결된 형태), 데바나가리어와 벵골어(결합) — 는 셰이핑 엔진이 없는 matplotlib로는 올바르게 그릴 수 없습니다. 올바른 폰트가 있어도 글리프가 연결되지 않고 순서가 잘못된 채로 출력됩니다. 이러한 언어는 `i18n.json` → `render.skip_figures`에 나열하세요. 해당 산문은 영향을 받지 않습니다. 해당 문서는 단순히 원본 이미지로 연결되며, [tools/translate_sync.py](../../tools/translate_sync.py)의 링크 수리가 자동으로 이를 가리킵니다. `hi`가 이 방식으로 설정되어 있습니다.
- **문자 가드:** [tools/i18n_render.py](../../tools/i18n_render.py)의 `SCRIPTS`는 각 언어의 라벨이 반드시 포함해야 할 문자를 기록합니다. 해당 문자가 전혀 없는 응답 — `ja` 섹션이 러시아어로 채워져 배포된 적이 있습니다 — 은 커밋되는 대신 거부되고 재시도됩니다. 해당 테이블에 없는 언어는 단순히 가드가 없으므로, `i18n.json`에 추가해도 절대 중단되지 않습니다. 검사를 받으려면 항목을 추가하세요.

## 5. 푸시 전 실행할 수 있는 검사

python tools/check_repo.py
```

번역 봇이 망가뜨릴 수 있고 다른 것으로는 잡을 수 없는 부분들을 검증합니다: 모든 상대 링크가 제대로 연결되는지, 모든 `labels.json` 섹션이 `i18n.json`과 일치하며 기본 섹션과 동일한 키와 동일한 `str.format` 플레이스홀더를 갖는지, 모든 정식 문서가 모든 언어에 미러를 갖는지, 그리고 모든 마크다운 파일이 언어 바를 포함하는지 확인합니다. CI는 두 워크플로에서 모두 이를 실행하며, 별도의 의존성이 필요 없습니다.

CI의 나머지 부분([ci.yml](../../.github/workflows/ci.yml))은 스크립트를 컴파일하고 전체 그림 파이프라인을 실행합니다. 커밋된 그림을 포함해 정확히 재현하려면 느슨한 버전이 아닌 고정된 툴체인을 설치하세요:

```bash
python -m pip install -r tools/requirements-ci.txt
